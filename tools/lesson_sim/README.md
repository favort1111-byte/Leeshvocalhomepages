레슨실(A1~A4) 서버 함수(`lesson_room_book` · `lesson_room_cancel` · `lesson_room_move` · `lesson_room_view` · `private.lesson_clash`)를
고치면 아래 두 가지를 다시 돌립니다. 실제 데이터는 바뀌지 않습니다.

1. **실제 서버, 되돌리는 거래** — `fuzz.sql`의 `__SEED__`(0~1) · `__N__`(번 수)을 바꿔 Management API로 실행.
   선생님(카카오 연결된 선생님) · 관리자가 섞여서 예약 · 한 번 빼기 · 이날부터 끝내기 · 전부 취소 · 한 번만 옮기기 · 정규 변경을
   아무렇게나 하고, 매번 앞으로 120일의 실제 수업에서 같은 방 · 같은 학생 · 같은 선생님 겹침이 0인지,
   선생님이 남의 학생 · 남의 예약을 건드리지 않았는지, 지난 날짜 · 시간이 바뀌지 않았는지, 보기 화면 수업 수가 맞는지 봄. 끝에 `rollback`.
2. **동시 접속 (로컬 Postgres 16)** — `rush.py`. 같은 방 · 같은 학생 · 같은 선생님에 동시에 몰리기, 연타, 빼기 · 옮기기와 예약이 동시에,
   24명이 300번씩 섞어서. 준비: 로컬 DB `lr`에 `base.sql` → 실제 서버의 레슨실 표 정의 → 실제 서버 함수(`pg_get_functiondef`)
   (`private.fail` · `hhmm` · `to_min` · `teaches` · `wd_name` · `lesson_allowed` · `lesson_clash` · `lesson_room_*`). 가짜 선생님 6 · 학생 120.

결과 (2026-11-24): 실제 서버에서 처음에 겹침 2가지를 찾아 고침 (`leesh_lesson_rooms_sim_fix`)
- 한 번 뺀 날을 첫날로 끝없는 정규를 잡으면 겹침 검사가 그 정규를 놓침 (`p_first = p_last`가 null)
- 이미 끝난 정규를 끝난 날 뒤로 "이날부터 시간 바꾸기" 하면 빈 기간으로 검사하고 끝없는 정규가 생김

   한 번 빼기 · 이날부터 끝내기 · 전부 취소 · 옮기기, 특정 날 휴무 넣기 · 지우기, 근무 시간 바꾸기를 섞어서 하고, **매번** 관리자 화면 값
